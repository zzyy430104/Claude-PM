# 浏览器端到端测试

用真实浏览器走完整业务流程，与 `apps/api/test` 里的接口测试互补。每个脚本对应一个交付批次：

| 脚本 | 覆盖 |
|---|---|
| `batchA.mjs` | 注册、登录、角色菜单、路由拦截、审计日志 |
| `foundation.mjs` | 新菜单、项目内 7 组导航与网址、职能角色、系统名称 |
| `initiation.mjs` | 立项申请、会签与批准、按类型模板生成计划草稿、交期倒排、可选工作包库、按角色指定责任人、计划对照项目要求检查与批准、项目要求变更、类型模板、立项与审批角色 |
| `costquality.mjs` | 成本策划（人工按费率、费用行、科目与目标成本检查）、工作包详情（成本 / 质量）、检验项与结果、不合格开不符合项、检验记录、工作包超支与承诺成本、职能角色费率、检验类别与检验项库 |
| `risks.mjs` | 项目目标（自动生成与自定义）、风险评价矩阵与重要度、应对策略与成本收益分析、措施、预警与触发、待复评与关闭、选“接受”的要求、逐级升级、企业风险（所有人可见）、风险管理设置 |
| `evaluation.mjs` | 部门与负责人、绩效评价设置、项目经理绩效（自动计分、按项目调整权重、管理层评语、调整分数与确认）、成员评价（打分、提交锁定、本人可见）、人事看评价单与导出 |
| `delivery.mjs` | 采购计划（物料、长周期、批准与修订、下单 / 到货 / 结算与承诺成本、逾期未下单、量产准备自动检查）、FAI 记录（有条件通过与遗留项）、售后交接（发起、接收人确认） |
| `comm.mjs` | 会议（发起例会含外部干系人、发送通知、参会确认、登记外部确认方式、纪要与行动项、生成下一次并带出未关闭行动项）、公告（发布、已读确认、提醒未读，成员不能发布） |
| `batchB.mjs` | 项目、阶段、成员、WBS、依赖、关键路径、甘特图、基线 |
| `batchC.mjs` | 关口评审、变更控制全流程、风险、问题、项目评审 |
| `batchD.mjs` | 成本、质量计划、不符合项闭环、沟通与培训 |
| `batchE.mjs` | 文档上传与版本、配置管理、经验教训 |
| `batchF.mjs` | 仪表盘与待办、通知、审核证据包下载 |
| `password.mjs` | 首次登录强制改密、个人设置改密、管理员重置密码 |
| `integration.mjs` | 需求、工作包四要素、计划批准与版本、按变更增删范围、变更草稿编辑、组织图、成本记到工作包 |
| `compare.mjs` | 质量 / 进度 / 成本三方面状态、挣值、甘特图基准对比、项目评审带数、关口评审汇总、企业阈值设置 |
| `completion.mjs` | 工作日历、里程碑、Excel 导入导出、WBS 模板、风险增强、SWOT、偏离通报、干系人、周报、资源负荷 |
| `i18nscan.mjs` | 英文界面下扫描各页面，列出未翻译的中文 |

## 运行

```bash
# 1. 启动后端和数据库（需要 PostgreSQL，见 ../../api/README 与根目录 README）
cd apps/api && npm run build && ALLOW_TENANT_SIGNUP=true node dist/main &
# 2. 启动前端
cd apps/web && npx ng serve &
# 3. 运行
cd apps/web && npm install && npm run e2e
```

环境变量：`WEB_URL`（默认 http://localhost:4200）、`API_URL`（默认 http://localhost:3000）、
`CHROMIUM_PATH`（浏览器可执行文件；不设则用 Playwright 安装的浏览器）。

脚本每次会用随机的企业标识自动建数据，可重复运行。登录一律走真实的登录表单（令牌只在内存和 httpOnly Cookie 里）。

## 对着已部署的站点运行

```bash
# 需要站点开启企业自助注册（ALLOW_TENANT_SIGNUP=true），脚本用它来建测试企业
WEB_URL=http://你的地址 API_URL=http://你的地址/api node e2e/batchC.mjs
```

nginx 对 `/api/auth/` 有访问频率限制（每 IP 每分钟 30 次，突发 20 次）。
连续跑多个脚本时，每个之间隔约一分钟，否则登录会被限流而误报失败。
